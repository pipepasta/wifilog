# wifilog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** macOS の Wi-Fi 品質（電波の値と遅延）を常駐して記録し、ratatui の TUI でリアルタイム表示（`view`）と過去期間の固定表示（`show-report`）ができる CLI を作る。

**Architecture:** 計測プロセス（`start --foreground`）が `log stream`（airportd の LQM）と `ping` ×2 の子プロセスをスレッドで読み、日ごとの JSON Lines ファイルに追記する。`view` / `show-report` はファイルを読むだけで、計測プロセスと直接通信しない。描画用のデータ（間引き・ネットワーク分割・統計）は純粋関数 `series::build` で作り、`view` と `show-report` は同じ `tui::draw` を使う。

**Tech Stack:** Rust（edition 2024、rustc 1.97.1）、ratatui 0.30（crossterm は `ratatui::crossterm` の再エクスポートを使う）、clap 4（derive）、serde / serde_json、chrono、anyhow、dirs、libc。開発用に tempfile。

**Spec:** `docs/superpowers/specs/2026-11-08-wifilog-design.md`

## Global Constraints

- 対象は macOS のみ。sudo なし、位置情報の許可なしで動くこと
- tokio などの非同期ランタイムは使わない（スレッド＋`std::sync::mpsc`）
- データディレクトリ: `dirs::data_local_dir()/wifilog`（= `~/Library/Application Support/wifilog/`）。環境変数 `WIFILOG_DIR` で上書き
- 日ごとのファイル名: `samples-YYYY-MM-DD.jsonl`（ローカル日付）
- 保存期間 30 日。計測プロセスの起動時と日付が変わったときに古いファイルを消す
- 計測の間隔は約 5 秒（LQM は OS が出す間隔、ping は `-i 5`）
- インターネット向け ping の既定の宛先は `1.1.1.1`。`--internet <HOST>` > 環境変数 `WIFILOG_INTERNET` > 既定 の順で優先
- ルーター向け ping は Wi-Fi インターフェースのゲートウェイ（`ipconfig getoption <dev> router`）に固定。Wi-Fi のゲートウェイと MAC アドレスは 30 秒ごとに確認
- `view` は 2 秒ごとに更新。時間幅は 5分 / 15分 / 1時間、既定は 15分
- `show-report` の期間は `--5m` / `--1h` / `--24h` / `--7d`（排他）。指定なしは `--1h`
- 画面は「縦に積む」5 段。全段の時刻の軸をそろえる
- ネットワークを混ぜた平均は表示しない
- 画面の文言は日本語
- 常駐プロセスの CPU 使用率は平常時 1% 未満が目安

## Review Focus

- `arp` が MAC アドレスの各オクテットを 0 埋めせずに出す（例: `0:1a:2b:3:4:5`）→ `00:1a:2b:03:04:05` に正規化して、同じルーターを別ネットワークと誤認しない（Task 2 にテスト）
- 表示期間が日付をまたぐ（`view` を 0 時前後に開く、`--24h` / `--7d`）→ 複数の日ごとのファイルから漏れなく読む（Task 3 にテスト）
- Wi-Fi が切れている・オフ（`ipconfig getoption` が空を返す）→ ルーター ping を止め、`net: null` の `net` レコードを書き、表示ではネットワーク `?` として扱う（Task 2・Task 4・Task 6 にテスト）
- 計測プロセスが `kill -9` などで落ちて pid ファイルが残る → ロックが取れれば `start` できる（pid ファイルの有無ではなくロックで判断）（Task 5 にテスト）
- 端末が小さい（高さ 12 行など）→ パニックせず、収まらない段を下から省く（Task 7 にテスト）

### Task 3: 保存（日ごとのファイル、保存期間、読み込み、追記分の追跡）

**Files:**

**Interfaces:**
- Consumes: `record::{Record, NetRecord}`
- Produces:
  - `store::data_dir() -> anyhow::Result<PathBuf>`（`WIFILOG_DIR` 優先）
  - `store::day_file(dir: &Path, date: NaiveDate) -> PathBuf`（`samples-YYYY-MM-DD.jsonl`）
  - `store::Appender::new(dir: PathBuf) -> Appender`、`Appender::append(&mut self, rec: &Record) -> anyhow::Result<()>`
    - レコードの `t` のローカル日付でファイルを選ぶ。日付が変わって新しいファイルを開いたとき、最後に追記した `NetRecord` があれば、その `net` / `router_ip` と今のレコードの `t` で `net` レコードを先頭に 1 件書く
    - 新しい日付のファイルを開いたときに `prune(dir, その日付, 30)` を呼ぶ
    - 1 行ごとに `write_all` で書き切る
  - `store::prune(dir: &Path, today: NaiveDate, keep_days: i64) -> anyhow::Result<Vec<PathBuf>>`: 日付が `today - keep_days` より前のファイルを消し、消したパスを返す
  - `store::load_range(dir: &Path, from: DateTime<FixedOffset>, to: DateTime<FixedOffset>) -> anyhow::Result<Vec<Record>>`: 期間にかかる日付のファイルをすべて読み、`from <= t <= to` のものを `t` の昇順で返す。読めない行は飛ばす
  - `store::Tail::new(dir: PathBuf) -> Tail`、`Tail::poll(&mut self) -> anyhow::Result<Vec<Record>>`: 今日のファイルの、前回読んだ位置より後の**改行で終わった行**だけを返す。途中の行は次回に持ち越す。日付が変わったら新しいファイルの先頭から読む

### Task 6: 描画用データの組み立て（`series`）

**Files:**
- Create: `src/series.rs`
- Modify: `src/main.rs`（`mod series;`）

**Interfaces:**
- Consumes: `record::*`
- Produces:
  - `series::Metric { Rssi, Snr, RouterMs, InternetMs, Cca, Tx, Retx, Fail }`（`Copy, Eq, Hash`）
  - `series::Window { pub from: DateTime<FixedOffset>, pub to: DateTime<FixedOffset> }`
  - `series::Stats { pub avg: f64, pub min: f64, pub max: f64 }`
  - `series::Network { pub label: char, pub mac: Option<String>, pub secs: i64 }`（`label` は出てきた順に `'A'`, `'B'`…。`mac` が `None` のものは `'?'`）
  - `series::Model { pub window: Window, pub networks: Vec<Network>, pub switches: Vec<(f64, char)>, pub lines: HashMap<Metric, Vec<Vec<(f64, f64)>>>, pub stats: HashMap<(Metric, char), Stats>, pub loss: HashMap<(Target, char), f64>, pub latest: HashMap<Metric, f64>, pub channel: Option<(u32, u32)>, pub last_record: Option<DateTime<FixedOffset>> }`
    - x 座標はすべて「`window.from` からの秒数」
    - `lines[m]` は線分（連続区間）のリスト。区間ごとに別のデータセットとして描く
    - `switches` はネットワークが切り替わった時刻の x と、切り替わり先の記号
    - `latest` は**最後のネットワーク**の、各指標の最新値
    - `channel` は最後の LQM の `(ch, bw)`
  - `series::build(records: &[Record], window: Window, buckets: usize) -> Model`
  - `pub const GAP_SECS: i64 = 15;`（同じ種類の記録の間隔がこれを超えたら線を切る）

アルゴリズム（テストが決めきれない部分）:
1. `window` 内のレコードを時刻順に走査し、`net` の変化で「ネットワーク区間」に分ける。区間ごとに記号を振り、`networks[].secs` に区間の長さを足す。区間の境目を `switches` に入れる（最初の区間の開始は入れない）
2. 区間の中で、指標ごとに前の点から `GAP_SECS` を超えて空いたら線分を切る
3. 間引き: 幅 `w = (to - from) / buckets` の区間に分け、線分の中で同じ区間に入った値をまとめる（Rssi/Snr/RouterMs/InternetMs/Cca/Tx は平均、Retx/Fail は合計）。点の x は区間の中央。ping の `ms: None` は平均に入れない
4. `stats` と `loss` は間引く前の値で、ネットワーク記号ごとに計算する（`loss` = タイムアウト数 ÷ その宛先の ping 総数）

### Task 7: 描画（`tui::draw`）

**Files:**
- Create: `src/tui/mod.rs`
- Modify: `src/main.rs`（`mod tui;`）

**Interfaces:**
- Consumes: `series::{Model, Metric, Network}`
- Produces:
  - `tui::Mode { Live { paused: bool, span_label: &'static str }, Report }`
  - `tui::draw(frame: &mut ratatui::Frame, model: &series::Model, mode: &Mode, now: DateTime<FixedOffset>)`
  - `tui::chart_buckets(area_width: u16) -> usize`（グラフの内側の幅 × 2。点字マーカー 1 文字 = 横 2 ドット）

画面の決まりごと（文言は固定）:
- 1 行目のヘッダー: 左に `wifilog ─ ルーター {mac 短縮} ─ ch{ch} {bw}MHz ─ {時間幅}`。MAC の短縮は `aa:bb:…:12`（先頭 2 オクテット … 最後の 1 オクテット）。右に、Live なら `● 計測中 HH:MM:SS`（一時停止中は `⏸ 一時停止`）、Report なら `期間 MM/DD HH:MM〜MM/DD HH:MM`
  - Live で `model.last_record` が `now` より 30 秒以上前、または `None` なら、右側を `⚠ 計測が止まっています`（`wifilog status` を促す）にする
- ネットワークが 2 つ以上のときだけ、2 行目に凡例: `A aa:bb:…:12 (5時間10分)  B cc:dd:…:34 (2時間05分)`
- 5 段の見出し（この順）: `RSSI / SNR`、`遅延（ルーター / インターネット）`、`チャンネル混雑度`、`送信速度`、`再送・失敗`
- 見出しの右の数字: ネットワークが 1 つなら Live は最新値、Report は `平均 x / 最小 y / 最大 z`。2 つ以上なら記号ごとの平均を、いた時間が長い順に 3 つまで（`A 2.8ms / B 14.1ms / 他 1`）。遅延の段はロス率も添える
- 各段は `Chart`（`Marker::Braille`、`GraphType::Line`）。x 軸の範囲はすべての段で `[0, window の秒数]`。`lines` の線分ごとに `Dataset` を作る。`switches` の x に縦線（2 点の `Dataset`）を引き、記号は 5 段目の上端付近ではなく 1 段目の見出し行に `▼B` のように載せてよい（位置の細部は任せる）
- 最下行のフッター: Live は `q 終了  ←/→ 時間幅  space 一時停止`、Report は `q 終了`
- 高さ: 5 段を均等に割り、1 段が 3 行未満になるなら下の段から省く
